# MySQL 运维实战：从零搭建到主从的完整闭环

## 项目定位

在 WSL2 Ubuntu 22.04 上从零搭建一套 MySQL 8.0 运维环境，覆盖安装部署、日常运维、SQL 优化、DDL 变更、备份恢复、时间点恢复、主从复制七组能力。数据集为 Sakila。每一项能力都对应一次实操演练，过程与结论保存在本仓库。

## 三组核心结论

**一、InnoDB 的行数类指标都是估算。** `SHOW TABLE STATUS` 与 `information_schema.TABLES` 的 `TABLE_ROWS` 来自采样外推，校验行数只用 `COUNT(*)`。同一机制在 `payment` 表行数、`EXPLAIN` 的 `rows`、`SHOW TABLE STATUS` 三处出现。

**二、DDL 的耗时差别来自操作要碰多少数据，不来自是否指定算法。** MySQL 在不写 `ALGORITHM` 时会自选最轻的方案，生产上显式写它的目的是当护栏，防止不满足条件时静默降级成 `COPY` 锁表。

**三、主从的双 `Yes` 只说明线程在跑，不代表数据一致。** 线程层看双 `Yes` 与状态句，数据层看 `CHECKSUM`，两层需要分别验证。只读约束管不住带 SUPER 权限的账号，需要 `super_read_only` 补齐。
